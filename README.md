# Ozon Performance — отчёт по рекламе с юнит-экономикой

Плейбук для Google Colab: [`oz_performance_report.ipynb`](oz_performance_report.ipynb) выгружает статистику рекламы из **Ozon Performance API** и (опционально) данные магазина из **Ozon Seller API**, после чего собирает Excel в формате привычного отчёта по Wildberries.

Ноутбук **только читает** данные: он не запускает и не отключает кампании, не меняет бюджеты, ставки и цены.

## Листы отчёта

| Лист | Что показывает | Источник |
|---|---|---|
| Сводка | Итоги периода: расход, выручка, ДРР, вердикты по кампаниям, блок экономики | расчёт |
| Кампании | ДРР, CPO, CTR, вердикт по целевому ДРР + **SKU кампании**, предельный ДРР, запас в п.п., прибыль с рекламы, вердикт экономики | Performance API |
| Товары | Статистика по SKU внутри кампаний (CPC и CPO), ставки, рекомендации + **маржа, предельный ДРР и прибыль по SKU** | Performance API |
| Ключи | Поисковые фразы кампаний «Вывод в топ» с рекомендациями | Performance API |
| Воронка | Как в отчёте WB: переходы в карточку → корзины → заказы → выкупы по каждому SKU + вклад рекламы и ДРР по SKU | Seller API |
| Экономика | Юнит-экономика SKU: цена, комиссия, логистика, эквайринг, налог, себестоимость → маржа до рекламы, предельный ДРР/CPO, прибыль | Performance API + Seller API + файл себестоимости |
| Диагностика | Статус каждого блока выгрузки: собрался лист или нет и почему. Формируется **всегда** | — |

## Два вопроса, на которые отвечает отчёт

1. **Эффективна ли кампания?** Лист «Кампании»: фактический ДРР против целевого (`TARGET_DRR`) — вердикты «Эффективна / Наблюдать / Неэффективна / Мало данных».
2. **Сходится ли реклама с экономикой?** Листы «Экономика», «Товары» и «Кампании»: по каждому SKU считается маржа до рекламы и **предельный ДРР** — уровень ДРР, при котором кампания крутится ровно в ноль. Вердикты «В плюс / Около нуля / В минус» и расчётная прибыль в рублях.

## Как связаны листы

Прибыль и предельный ДРР проставляются сразу на трёх уровнях, поэтому переносить их между листами формулами не нужно:

| Лист | Ключ строки | Колонки экономики |
|---|---|---|
| Экономика | SKU | маржа, предельный ДРР/CPO, прибыль с рекламы по всему SKU |
| Товары | кампания + SKU | `Маржа/шт, ₽`, `Предельный ДРР %`, `Запас ДРР, п.п.`, `Прибыль с рекламы`, `Экономика` |
| Кампании | ID кампании | `Предельный ДРР %` (взвешен по выручке SKU кампании), `Запас ДРР, п.п.`, `Прибыль с рекламы`, `Покрытие экономикой %`, `Экономика` |

На листе «Кампании» есть колонки `SKU (основной)` (SKU с наибольшей выручкой в кампании), `Товар (основной)`, `SKU в кампании, шт` и `Все SKU` — по ним лист связывается с «Товарами» и «Экономикой», если нужен свой расчёт.

## Методика предельного ДРР

Маржа до рекламы на одну проданную штуку:

```
маржа = средняя цена продажи (выручка рекламы ÷ заказы, иначе цена из файла или карточки)
      − комиссия Ozon (% от цены по схеме FBO/FBS)
      − логистика (среднее магистрали + последняя миля)
      − эквайринг
      − налог (TAX_RATE_PCT × цена)
      − себестоимость (файл cost_prices.csv, иначе DEFAULT_COST_SHARE_PCT × цена)
      − EXTRA_COST_PER_UNIT (упаковка, обработка)
```

- **Предельный ДРР, %** = маржа ÷ цена × 100. Фактический ДРР ниже — реклама в плюс, выше — в минус.
- **Предельный CPO, ₽** = маржа — максимально допустимая цена заказа.
- **Прибыль с рекламы, ₽** = маржа × заказы − расход на рекламу.
- Для кампании предельный ДРР взвешивается по выручке её SKU; колонка «Покрытие экономикой %» показывает долю рекламной выручки с известной маржой.
- Порог `BREAKEVEN_SAFETY_PP` (по умолчанию 2 п.п.) задаёт коридор «Около нуля».

Ограничения: возвраты и невыкупы в маржу не включены; логистика и эквайринг из Seller API — оценки Ozon для текущей цены, фактические удержания смотрите в финансовых отчётах.

## Откуда берутся комиссия, логистика и себестоимость

Источник выбирается по SKU и подписан в колонках «Источник комиссии и логистики» и «Источник себестоимости»:

| Показатель | 1. Seller API | 2. Файл `cost_prices.csv` | 3. Допущение |
|---|---|---|---|
| Цена | цена карточки | колонка `цена` | средний чек рекламы (выручка ÷ заказы) — приоритетнее всего, когда были заказы |
| Комиссия, % | `v5/product/info/prices` по схеме FBO/FBS | колонка `комиссия` | `DEFAULT_COMMISSION_PCT` |
| Логистика, ₽ | магистраль + последняя миля | колонка `логистика` | `DEFAULT_LOGISTICS_PER_UNIT` |
| Эквайринг, ₽ | поле `acquiring` | колонка `эквайринг` | `ACQUIRING_PCT` от цены |
| Себестоимость, ₽ | — | колонка `себестоимость` | `DEFAULT_COST_SHARE_PCT` от цены |

**Экономика считается и без Seller API.** Если секретов `OZON_SELLER_CLIENT_ID` / `OZON_SELLER_API_KEY` нет, лист «Экономика» всё равно собирается по среднему чеку рекламы и допущениям (переключатель `ECON_FALLBACK_WITHOUT_SELLER_API`). Без Seller API пропадает только лист «Воронка».

## Файл себестоимости

- Формат: CSV (разделитель `;` или `,`, десятичная запятая допускается) либо XLSX. Образец — [`cost_prices.example.csv`](cost_prices.example.csv).
- Обязательно: ключ `sku` **или** `артикул` и колонка `себестоимость`.
- Необязательно: `цена`, `комиссия`, `логистика`, `эквайринг` — они перекрывают допущения для конкретного SKU.
- Без Seller API артикулы в отчёте неизвестны, поэтому сопоставление идёт по `sku` (Ozon SKU) — он есть на листах «Товары» и «Экономика».
- Если файла нет, первый запуск создаст шаблон `cost_prices_template.csv` со всеми SKU из рекламы, их названиями и средней ценой продажи. Заполните колонку `себестоимость`, переименуйте файл в `cost_prices.csv` и загрузите обратно в сессию Colab.

## Настройка

1. Кабинет Ozon Seller → **Настройки → API-ключи → Performance API** → создайте сервисный аккаунт.
2. В Colab (панель слева → Секреты) добавьте `OZON_PERF_CLIENT_ID` и `OZON_PERF_CLIENT_SECRET`, включите доступ из блокнота.
3. *(Для воронки и точных комиссий)* создайте ключ **Seller API** и добавьте секреты `OZON_SELLER_CLIENT_ID` и `OZON_SELLER_API_KEY`. Без них отчёт соберётся без листа «Воронка», а экономика посчитается по допущениям.
4. *(Для точной экономики)* загрузите в сессию Colab файл `cost_prices.csv` — см. раздел выше.
5. Задайте период и параметры в ячейке **Параметры** → **Среда выполнения → Выполнить все** → в конце скачается `.xlsx`.

## Параметры экономики

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `SALES_SCHEME` | `FBO` | Схема продаж для комиссии и логистики (`FBO`/`FBS`) |
| `TAX_RATE_PCT` | `6.0` | Налог с выручки (УСН «доходы»); 0 — не учитывать |
| `DEFAULT_COST_SHARE_PCT` | `30.0` | Себестоимость как % цены для SKU без строки в файле; 0 — не подставлять допущение |
| `EXTRA_COST_PER_UNIT` | `0.0` | Прочие затраты на штуку, ₽ |
| `BREAKEVEN_SAFETY_PP` | `2.0` | Коридор «около нуля» вокруг предельного ДРР, п.п. |
| `COST_FILE` | `cost_prices.csv` | Имя файла себестоимости в сессии Colab |
| `COST_TEMPLATE_FILE` | `cost_prices_template.csv` | Куда сохранить шаблон себестоимости, если файла нет |
| `ECON_FALLBACK_WITHOUT_SELLER_API` | `True` | Считать экономику даже без секретов Seller API |
| `DEFAULT_COMMISSION_PCT` | `15.0` | Комиссия Ozon, % — когда её неоткуда взять |
| `DEFAULT_LOGISTICS_PER_UNIT` | `80.0` | Логистика на штуку, ₽ — когда её неоткуда взять |
| `ACQUIRING_PCT` | `1.5` | Эквайринг, % от цены — когда его неоткуда взять |

## Если лист не собрался

Откройте лист **Диагностика** — он есть в каждом отчёте. Там по каждому блоку написано, собрался он или нет и почему: подключён ли Seller API, сколько строк пришло с ценами, найден ли файл себестоимости, из чего посчитана экономика, какие разделы упали с ошибкой. Тот же вывод дублируется в блоке «Экономика» листа «Сводка».

## Замечания по API

- Полный набор метрик воронки (`/v1/analytics/data`: переходы в карточку, корзины, выкупы, позиция) доступен на подписке **Premium Plus**; без неё ноутбук автоматически откатывается на базовые метрики (заказы и выручка).
- Асинхронные отчёты Performance API формируются последовательно из-за лимита одновременных выгрузок; период одной выгрузки — до 62 дней.
- Денежные значения ставок и бюджетов переводятся из миллионных долей рубля в рубли.
